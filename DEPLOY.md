# Deploying NCCMS on Render with MongoDB Atlas

One Render **web service** runs everything: the API *and* the website (the backend serves the built React app), so there is a single URL and no CORS setup. Images are stored in MongoDB, so they survive Render restarts.

Total time ≈ 20 minutes. Everything below works on the free plans.

---

## 1. MongoDB Atlas (the database)

1. Sign up at <https://www.mongodb.com/cloud/atlas/register> and create a **free M0 cluster** (choose a region near you, e.g. *Mumbai* / *Singapore*).
2. **Database Access → Add New Database User**: username e.g. `nccms`, password = *Autogenerate* or your own. Role: **Read and write to any database**.
   *Tip: letters and digits only in the password avoids URL-encoding problems.*
3. **Network Access → Add IP Address → Allow access from anywhere (`0.0.0.0/0`)**. Render's free plan has no fixed IP, so this is required. (The database user's password is what protects it — use a strong one.)
4. **Database → Connect → Drivers** and copy the connection string. It looks like:

   ```
   mongodb+srv://nccms:<password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority
   ```
   Replace `<password>` with the real password and add the database name **`/nccms`** before the `?`:

   ```
   mongodb+srv://nccms:YourPassword@cluster0.abcde.mongodb.net/nccms?retryWrites=true&w=majority
   ```
   Keep this — it is your `MONGO_URI`.

## 2. Put the project on GitHub

Render deploys from a Git repository.

```bash
cd NCCMS
git init
git add .
git commit -m "NCCMS"
```
Create an empty repository on <https://github.com/new> (private is fine), then:

```bash
git branch -M main
git remote add origin https://github.com/<your-username>/nccms.git
git push -u origin main
```
`.gitignore` already keeps `node_modules`, `.env` files and uploads out of the repository, so no secrets are pushed.

## 3. Render (the server)

1. Sign up at <https://render.com> and connect your GitHub account.
2. **New + → Blueprint** → choose your `nccms` repository → **Apply**. Render reads `render.yaml` and asks for two values:

   | Variable | What to enter |
   |---|---|
   | `MONGO_URI` | the Atlas connection string from step 1 |
   | `SUPER_ADMIN_PASSWORD` | a strong password (10+ characters) for the first Super Admin |

   Everything else (`JWT_SECRET`, `NODE_ENV`, auto-seed…) is filled in for you.
3. Wait for the first deploy (5–8 minutes). When the log says `NCCMS backend running` and `MongoDB connected`, open the `https://nccms-xxxx.onrender.com` address Render shows.

> Prefer clicking through instead of a Blueprint? **New + → Web Service** → pick the repo → *Runtime* **Node**, *Build Command* `npm run build`, *Start Command* `npm start`, *Health Check Path* `/api/health`, then add the environment variables from the table below.

## 4. First login

On the login page click **Authorized Administration** and sign in with:

* email: `superadmin@nccms.gov.in` (or whatever you set in `SUPER_ADMIN_EMAIL`)
* password: the `SUPER_ADMIN_PASSWORD` you entered

The first start created the departments, complaint categories, national leadership and this Super Admin automatically. **No demo accounts are created on a hosted site** (their passwords would be public) — create real Admins, Officers and Citizens from the Super Admin portal.

## Environment variables

| Variable | Required | Notes |
|---|---|---|
| `MONGO_URI` | yes | Atlas connection string ending in `/nccms` |
| `JWT_SECRET` | yes | long random text; generated by the Blueprint. The server refuses to start in production with a weak one |
| `NODE_ENV` | yes | `production` |
| `SUPER_ADMIN_PASSWORD` | first start | 10+ characters; used once, when no Super Admin exists |
| `SUPER_ADMIN_EMAIL` | no | default `superadmin@nccms.gov.in` |
| `AUTO_SEED` | no | `true` creates reference data + Super Admin on first start |
| `SEED_DEMO_DATA` | no | keep `false` on a public site |
| `AUTO_CLOSE_HOURS` | no | hours a Resolved complaint waits before auto-closing (default 42) |
| `UPLOAD_STORAGE` | no | `db` (default in production) keeps images in MongoDB |
| `CLIENT_URL` | no | only if the website is on a *different* domain than the API |
| `GOOGLE_API_KEY` | no | enables the Gemini-powered AI assistant; the built-in assistant works without it |

## Updating the site

Commit and push — Render rebuilds and redeploys automatically:

```bash
git add . && git commit -m "Update" && git push
```

## Things to know about the free plan

* **Sleeps after ~15 minutes idle.** The next visit takes 30–60 seconds to wake it. Upgrading the service to *Starter* keeps it always on.
* The **42-hour auto-close** check runs every 10 minutes while the service is awake, and immediately on every wake-up, so nothing is missed — a complaint may just close a little late if the site was asleep.
* Atlas M0 gives 512 MB. Images are limited to 5 MB each and stored in the database, so keep an eye on usage (Atlas → Metrics) if you expect many photos.

## Custom domain

Render → your service → **Settings → Custom Domains** → add the domain and create the DNS record Render shows. HTTPS is automatic.

## Seeding or re-seeding by hand

From your Mac, against Atlas (safe to repeat — it only fills in what is missing):

```bash
cd backend
NODE_ENV=production MONGO_URI="mongodb+srv://…/nccms" SUPER_ADMIN_PASSWORD="YourStrongPassword" npm run seed
```

## Troubleshooting

| Symptom (Render logs) | Cause / fix |
|---|---|
| `JWT_SECRET is missing or too weak` | set `JWT_SECRET` to a random string of 24+ characters |
| `MongoDB connection error … bad auth` | wrong Atlas username/password — re-check, or reset the database user's password |
| `MongoDB connection error … ENOTFOUND` / `timed out` | Atlas *Network Access* must allow `0.0.0.0/0`; check the cluster host name in `MONGO_URI` |
| `AUTO_SEED needs SUPER_ADMIN_PASSWORD` | set `SUPER_ADMIN_PASSWORD` (10+ characters) and redeploy |
| Build fails with `vite: not found` | the Build Command must be `npm run build` (it installs the frontend's dev tools) |
| Site loads but login says "Invalid email or password" | the Super Admin was not created — check the log for the seeding messages; the password is the one in `SUPER_ADMIN_PASSWORD` |
| Uploaded photos vanish after a redeploy | make sure `UPLOAD_STORAGE` is not set to `disk` |
